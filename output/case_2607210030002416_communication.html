안녕하세요 백광제 고객님, 한국마이크로소프트 고객기술지원 문소영 입니다.  

 

이슈가 해결된 점을 확인해주셔서 감사합니다. 이슈가 해결된 만큼, 아래와 같이 정리하여 케이스를 종료하고자 합니다. 종료 이후에도 동일한 문제가 다시 발생하거나 추가로 궁금한 사항이 있으시면 재오픈을 도와드리겠습니다. 

 

문의 종료 후에는 지원 경험에 대한 간단한 웹 설문을 요청하는 메일을 받으실 수 있습니다. 잠시 시간을 내어 응답해 주시면, 고객님의 소중한 의견을 반영하여 저희 고객기술지원 서비스를 지속적으로 개선하는 데 활용하겠습니다. 

 

문의 번호: 

 2607210030002416

 

문의 사항: 

  build-external container 에 blob data contributor 권한을 할당한 Managed Identity 를 이용하여, VM 에서 Managed Identity 로 로그인 후 az storage blob list 명령어 수행 시 'Response status|AuthorizationFailure' 에러 발생

 

자체 확인한 사항

- 네트워크: Private Endpoint(pe-staz02amlliamak02-blob-01, 10.249.24.108) 및 Private DNS

  A 레코드 정상 등록 확인, TLS handshake 성공 확인함

- 컨테이너/데이터 자체 문제 여부: 계정 키(Shared Key)로 우회 접근 시에는 정상 조회됨

 

 

결과 요약: 

 전달해 주신 자료와 서버 측 로그(Request ID: f0fe2353-f01e-001d-7dab-199806000000)를 분석한 결과를 공유드립니다.

 

원인:

이번 오류는 권한(RBAC)이나 인증(Managed Identity) 문제가 아니라, 스토리지 계정의 네트워크 규칙에서 요청이 차단된 것으로 확인됩니다. 서버 로그상 인증(OAuth)은 정상 통과했으나, 요청이 승인된 Private Endpoint 경로로 인식되지 않아("No matched VNet in PrivateLink configuration found") 기본 동작(Deny)에 따라 403이 반환되었습니다.

 

가상 머신(vm-az02-rnd-cstb-nc-01)은 vnet-az02-rnd-cstb-01 네트워크에 있고, 스토리지의 Private Endpoint는 다른 네트워크(vnet-az02-rnd-liamak-01)에 있습니다. 두 네트워크는 서로 직접 연결되어 있지 않고, 중간의 허브 네트워크(vhub-az02-rndgov-01)를 거쳐 통신합니다.

 

이 과정에서 요청이 허브를 경유하며 출발지 주소가 바뀌어(10.249.4.135) 전달됩니다. 그 결과 스토리지는 이 요청을 Private Endpoint를 통한 정상 연결로 보지 못하고, 허용되지 않은 주소로 판단하여 차단하는 것으로 보입니다.

 

 

권장 구성:

가상 머신이 있는 네트워크(vnet-az02-rnd-cstb-01)에 이 스토리지의 blob용 Private Endpoint를 새로 하나 생성하는것을 제안드립니다.

프라이빗 엔드포인트 사용 - Azure Storage | Microsoft Learn

 

참고로 ADLS Gen2 계정의 경우 blob 외에 dfs 리소스용 Private Endpoint도 함께 필요할 수 있어, 두 리소스 모두 구성 검토를 권장드립니다.

 

이후 Private Endpoint 생성 후 Private Link를 통해 대상 Storage Account로 접근이 가능한 점 확인해 주셨습니다.

 

케이스 진행에 협조해 주셔서 감사드리며, 오늘도 좋은 하루 보내시길 바랍니다 😊 

 

저희 서비스를 이용해 주셔서 다시 한번 감사드립니다.
