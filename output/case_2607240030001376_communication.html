Assessment Mode : ImageDefault
Patch Mode: AutomaticByOS (Windows Automatic updates)
EnableAutomaticUpdates: True


해당 VM은 생성 시 사용된 이미지 기본값에 따라 업데이트가 자동으로 수행되고 있으며, Azure Update Manager를 통해 중앙 관제되는 것과 별도로 자동 업데이트 기능이 동작 중인 것으로 파악하였습니다. AUM 내 중앙 관제를 원하신다면 'Azure Managed 옵션을 선택해주십시오.
이에 따라 AUM 메뉴 내 히스토리가 비어 있더라도 실제로 업데이트는 OS 내부 설정에 따라 이루어졌을 가능성이 높아 알려주신 시나리오와도 부합하는 내용으로 보입니다.


해당 설정을 포털 UI상에서 보거나 수정하시려면 해당 VM 내 Operation > Updates 메뉴에서 Update settings 버튼 선택으로 확인 부탁드립니다:
Periodic assessment
Patch orchestration (AUM 사용시 매니지드 옵션 선택)
EnableAutomaticUpdates : 이 설정값은 VM 생성시에만 변경이 가능한 값이라 변경하시려면 해당 VM을 새로 생성하셔야 한다고 합니다.

Azure Virtual Machines 및 확장 집합에 대한 자동 게스트 패치 - Azure Virtual Machines | Microsoft Learn


Assessment 가 정상 수행되는 것과 스크린샷 내 최신 버전의 폴더들이 존재하는 것으로 보아 VM 확장도 올바르게 설치되어 동작 중입니다.


파워쉘 관련해서는 해당 VM에서 Azure 엔드포인트로 Outbound 연결이 잘 되시는 지 확인이 필요할 것 같습니다.

마이크로소프트 기술지원에 문의 주셔서 감사합니다. 저는 이번 케이스를 지원할 이진모 엔지니어입니다.

 

관련 내용을 다음과 같이 정리하여 보내 드리니 내용을 살펴보시고 문의사항이 있으시면 언제든지 연락주시기 바랍니다.

 

[요청내용]

Azure update Manager설정 중입니다.

현재 periodic assessment는 disable이고 patch orchestration은 Windows automatic updates 입니다. 이런 설정일 때도 자동으로 업데이트가 진행되는지 문의 드립니다.

 

혹시나 Periodic assessment를 enable해야 자동 업데이트가 되는지 확인을 하기 위함 입니다.

 

[최초 답변]

Azure Update Manager로 VM을 관리하시기 위해서는 해당 VM에 Update Manager VM 확장이 설치가 되어야 합니다.

이 확장이 설치가 안된 상태라면 보통 Periodic Assessment가 No로 표시가 되며, 자체 OS 내 설정을 따라 갑니다. 

기본 윈도우 설정에서 자동 업데이트가 활성화되어 있는 경우에는 Azure Update Manager를 사용하지 않더라도 운영체제 자체 기능에 의해 업데이트가 자동으로 설치될 수 있습니다.

 

혹시 이와 다른 현상을 발견하셨다면, 아래 정보 확인 부탁드립니다:

해당 VM 의 리소스 ID
해당 VM 내 VM 확장 설치 여부 확인
포털 > 해당 VM > Operations > Run command > RunPowerShellScript > 아래 스크립트 실행
$InstallPath ='C:\WindowsAzure\Logs\Plugins\Microsoft.Cplat.Core.WindowsPatchExtension'
if(Test-Path $InstallPath -PathType Container){Get-ChildItem $InstallPath}
혹은 해당 VM에 직접 접근 하셔서 위 폴더 내 파일이 있는지 확인 부탁드립니다.
해당 VM > Operations > Updates > History 탭 내 레코드 확인

 

[다음단계]

추가 문의사항이 있으시면 반드시 전체회신 부탁드립니다.
