1. Agentless VM Scanning 외의 탐지 방식

Azure VM에 대한 악성코드 탐지 경로는 크게 두 가지로 구분됩니다.

(1) 에이전트 기반 탐지(Microsoft Defender for Endpoint)
Defender for Servers Plan 1 및 Plan 2에는 Microsoft Defender for Endpoint Plan 2의 기능(EDR 포함)이 포함되며, 구독에서 Defender for Servers 플랜을 사용하도록 설정하면 지원 대상 머신에 MDE.Windows 또는 MDE.Linux 확장이 자동으로 배포됩니다. Windows Server에서는 Microsoft Defender 바이러스 백신이 active mode로, Linux에서는 MDE의 맬웨어 방지 구성 요소가 passive mode로 구성됩니다.
참고: https://learn.microsoft.com/ko-kr/azure/defender-for-cloud/faq-defender-for-servers 

 

(2) 에이전트리스 탐지(Agentless malware scanning)
Defender for Servers Plan 2에서 Agentless scanning이 활성화된 경우 제공됩니다. Defender CSPM 플랜만 사용하는 경우 악성코드 스캔은 포함되지 않습니다.
참고: https://learn.microsoft.com/ko-kr/azure/defender-for-cloud/agentless-malware-scanning 

 

또한 Agentless machine scanning은 악성코드 외에도 EDR 설정 점검, 소프트웨어 인벤토리, 취약성 평가, 시크릿 검색을 동일한 디스크 스냅샷 기반 인프라에서 함께 수행합니다.
참고: https://learn.microsoft.com/ko-kr/azure/defender-for-cloud/concept-agentless-data-collection 

 

참고로 Defender for Storage의 악성코드 스캔은 업로드 시점(on-upload)에 동작하나, 이는 스토리지 계정을 대상으로 하는 별도 플랜이며 Azure VM 디스크에는 적용되지 않습니다.

 

2. Agentless VM Scanning의 수행 기준

Agentless VM Scanning은 이벤트 기반이 아니라 정기 스케줄 기반으로 동작합니다.

·       스캔은 24시간마다 1회 수행되며, 이 주기는 고객이 변경할 수 없습니다(nonconfigurable schedule).

·       스캔 유형은 quick scan과 full scan 두 가지가 있으며, 두 유형은 서로 다른 주기로 수행됩니다.

·       실행 중이 아닌 VM(중지/할당 취소 상태)은 스캔되지 않습니다.

·       아래 조건에 해당하는 VM 또는 디스크는 스캔 대상에서 제외되거나 일부만 스캔됩니다.
- 전체 디스크 용량 4TB 초과(초과 시 OS 디스크가 4TB 미만인 경우 OS 디스크만 스캔)
- 디스크 개수 14개 초과
- UltraSSD_LRS, PremiumV2_LRS, AKS Ephemeral OS Disk
- UFS, ReFS, ZFS 파일 시스템
- OracleASM, DRBD, Linux_Raid_Member 등

참고: https://learn.microsoft.com/ko-kr/azure/defender-for-cloud/enable-agentless-scanning-vms

 

또한 테스트 파일을 이용한 검증 시 경고는 24시간 이내에 표시되는 것으로 문서화되어 있습니다.
참고: https://learn.microsoft.com/ko-kr/azure/defender-for-cloud/test-agentless-malware-scanning

 

3. 실시간 탐지 기능과 Agentless VM Scanning의 차이

실시간 악성코드 탐지는 Agentless VM Scanning이 아니라 VM 내부에 배포되는 Microsoft Defender for Endpoint(Defender 바이러스 백신)의 차세대 보호 기능으로 제공됩니다. 공식 문서에서도 Agentless malware scanning은 에이전트 기반 Defender for Endpoint 보호에 "추가로(in addition to)" 제공되는 기능으로 명시되어 있으며, 실시간 보호를 대체하는 기능이 아닙니다.

 

두 방식의 관계는 다음과 같습니다.

(1) 탐지 엔진: Agentless malware scanning은 별도의 독립 엔진이 아니라 Microsoft Defender 바이러스 백신 엔진과 고급 클라우드 보호를 동일하게 사용합니다.
(2) 동작 위치: Agentless는 디스크 스냅샷을 생성하여 VM 외부(클라우드 측)에서 검사하며, 검사가 끝나면 스냅샷을 즉시 삭제합니다. 반면 Defender 바이러스 백신은 VM 내부에서 파일 접근 시점에 실시간으로 검사합니다.
(3) 탐지 시점: Agentless는 24시간 주기 스케줄에 따라 검사하므로 파일이 생성된 즉시 탐지되지 않을 수 있습니다. 실시간 탐지는 파일 접근 시점에 동작합니다.24
(4) 커버리지: Agentless는 바이러스 백신이 설치되지 않은 머신도 검사할 수 있고, 에이전트 기반 검사에서 제외(exclusion)된 파일과 폴더까지 포함하여 검사하며, 머신 성능에 영향을 주지 않습니다.

참고: https://learn.microsoft.com/ko-kr/azure/defender-for-cloud/agentless-malware-scanning 

 

4. 5월 업로드 파일이 7월 27일에 탐지된 원인

일반적인 동작 원리는 다음과 같습니다.

특정 파일의 탐지 여부는 해당 검사가 실제로 수행된 시점에 Defender가 보유하고 있던 탐지 능력(시그니처 및 클라우드/머신러닝 기반 휴리스틱)에 따라 결정됩니다. 탐지 인텔리전스는 지속적으로 갱신되므로, 파일이 변경되지 않았더라도 이전 검사에서는 탐지되지 않고 이후 검사에서 탐지될 수 있습니다.

또한 동일한 머신과 동일한 위협 조합에 대해서는 경고 과다를 방지하기 위해 경고가 반복 생성되지 않습니다.

따라서 문의하신 사례는 "파일 업로드 이후 탐지 인텔리전스가 갱신되었고, 갱신 이후 수행된 정기 스캔에서 해당 파일이 탐지된 경우"에 해당할 가능성이 높습니다. 다만 이는 현재 시점의 유력한 가설이며, 확정을 위해서는 해당 VM의 실제 스캔 이력 확인이 필요합니다. Agentless 스캔은 검사 직후 디스크 스냅샷을 삭제하므로, 5월 시점에 해당 파일이 디스크에 존재했는지 여부를 사후에 직접 확인할 수는 없습니다.

- 도구에 포함된 스크립트는 모두 Microsoft 서명이 적용되어 있으며, 파일이 변경된 경우 서명 검증 오류로 종료됩니다. 다운로드한 파일을 수정하지 마시고 그대로 실행해 주십시오.

7. 생성된 진단 패키지 .zip 파일은 /tmp 디렉터리에 저장됩니다. 해당 파일을 회신해 주시기 바랍니다.
