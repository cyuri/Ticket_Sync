I have completed an initial analysis of the Confidential VM backup validation failure ("Azure Backup could not get access to key vault / managed HSM associated with some of the selected confidential VM(s)") for VM cvm-test-rhel-app.

Most important finding

The Managed HSM RBAC you configured is actually correct — it is not the cause. You assigned the built-in role Managed HSM Crypto User to Backup Management Service at scope /. I verified against the Managed HSM built-in-roles matrix that this role already grants both data actions Azure Backup requires for a Confidential VM:

Microsoft.KeyVault/managedHsm/keys/read/action

Microsoft.KeyVault/managedHsm/keys/backup/action

Scope / is HSM-wide and covers the key. So the role, scope, and principal you set are valid and sufficient — the failure is not a wrong-role problem.

Where the validation failure actually comes from

Because your RBAC is correct, the wizard is failing preflight for one of the following reasons (in order of likelihood). Confirming a few data points below will let us isolate it quickly:

RBAC propagation delay — Managed HSM local-RBAC changes take time to propagate. Please wait 15–30 minutes after the assignment and re-run validation.

Principal identity — the "Backup Management Service" assignment must resolve to AppId 262044b1-e2ce-469f-a196-69ab7ada62d3 in your tenant. Please confirm the object/app ID shown on the mHSM role assignment.

DES → key → HSM chain — the CVM OS disk uses a Disk Encryption Set (type ConfidentialVmEncryptedWithCustomerKey) that points to a specific key. If that key lives in a different vault/HSM than HSM-az01-azsec-mHSM-01, granting on this HSM will not help. Please share the OS-disk DES resource ID and the key (HSM + key name) it references.

VM size — Confidential VM backup supports v6-series only; v5-series (DCasv5 / ECasv5) is not supported and fails validation. Please confirm the exact VM size/SKU of cvm-test-rhel-app.

"CVM v2 opt-out" subscription feature flag — backup/restore fail when this flag is enabled for the subscription. Please confirm it is not set.

Preview feature RestorePointSupportForConfidentialVMV2 (Microsoft.Compute) must read Registered (not Registering).

Please provide

Exact VM size/SKU of cvm-test-rhel-app.

OS-disk Disk Encryption Set resource ID and the key (HSM + key name) it references; confirm the key is in HSM-az01-azsec-mHSM-01.

가장 중요한 확인 사항

고객님께서구성하신 Managed HSM RBAC은 실제로올바르며, 이번오류의원인이아닙니다. 고객님은기본제공역할Managed HSM Crypto User를Backup Management Service 주체에범위/로할당하셨습니다. Managed HSM 기본 역할 매트릭스를 확인한 결과, 이역할은 Confidential VM 백업에 필요한 두가지데이터작업을모두이미포함하고있습니다:

Microsoft.KeyVault/managedHsm/keys/read/action

Microsoft.KeyVault/managedHsm/keys/backup/action

범위/는 HSM 전체범위이므로해당키를포함합니다. 따라서고객님이설정하신역할, 범위, 주체는유효하고충분하며, 이번실패는역할(권한) 설정오류가아닙니다.

유효성 검사 실패의 실제 원인

RBAC이올바르므로, 아래원인중하나로사전검사(preflight)에서실패하는것으로추정됩니다 (가능성이높은순서). 아래정보를확인해주시면신속하게원인을좁힐수있습니다:

RBAC 전파 지연 — Managed HSM 로컬 RBAC 변경은 전파에 시간이 걸립니다. 할당 후 15–30분 기다린 뒤 유효성 검사를 다시 실행해 주세요.

주체(Principal) ID 확인 — "Backup Management Service" 할당이 테넌트 내에서 AppId 262044b1-e2ce-469f-a196-69ab7ada62d3로 정확히 확인되어야 합니다. mHSM 역할 할당에 표시된 개체/앱 ID를 확인해 주세요.

DES → 키 → HSM 연결 — CVM OS 디스크는 특정 키를 참조하는 Disk Encryption Set(유형: ConfidentialVmEncryptedWithCustomerKey)을 사용합니다. 해당 키가 HSM-az01-azsec-mHSM-01이 아닌 다른 볼트/HSM에 있다면 이 HSM에 권한을 부여해도 해결되지 않습니다. OS 디스크의 DES 리소스 ID와 참조하는 키(HSM + 키 이름)를 공유해 주세요.

VM 크기 — Confidential VM 백업은 v6 시리즈만 지원하며, v5 시리즈(DCasv5 / ECasv5)는 지원되지 않아 유효성 검사에서 실패합니다. cvm-test-rhel-app의 정확한 VM 크기/SKU를 확인해 주세요.

"CVM v2 opt-out" 구독 기능 플래그 — 이 플래그가 구독에 설정되어 있으면 백업/복원이 실패합니다. 설정되어 있지 않은지 확인해 주세요.
