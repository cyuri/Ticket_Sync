기술지원 서비스를 이용해 주셔서 감사합니다.

엔지니어가 고객께 전화를 드릴 때 수신번호가 1577-9700으로 표시되며,  상담내용은 고객지원 및 서비스 개선 등을 위해 녹음되며,

관련 법안에 따라 일정기간 보관됩니다.

 

문의하신 내용에 대해 아래와 같이 정리합니다. 잘못 이해한 부분이 있으면 알려 주시기 바랍니다.

 

 

[문의번호]

2607290030005200 

 

[문의사항]

같이 첨부드리는 이미지에서의 프로세스 확인 및 메모리 점유 완화를 위한 방안 안내 부탁드립니다.

 

현재 확인한 프로세스

Antimalware Service Executable, WMI, RPC, Windows Modules Installer Worker: Windows Server 기본 내장 보안 검사/시스템 관리/업데이트 프로세스

 

Windows Defender Advanced Threat Protection 관련 서비스(MsSense.exe): Microsoft Defender for Endpoint(MDE) 센서 프로세스, Azure 구독에 Microsoft Defender for Cloud의 Defender for Servers 플랜이 활성화되면 Defender for Endpoint 통합 기능을 통해 자동 배포되는 Microsoft 정품 보안 프로세스

 

서비스호스트: UtcSvc(Connected User Experiences and Telemetry): Windows 진단 데이터 수집/전송을 담당하는 OS 기본 내장 서비스, 조직 정책으로 수집 레벨(Security/Basic/Enhanced/Full)을 조정할 수 있는 정상 시스템 구성 요소

 

확인하여 관련 담당자에 1차 공유내용

위 프로세스들은 모두 Windows OS 및 Microsoft Defender for Endpoint(MDE) 관련 정상 프로세스로 확인함(미상 프로그램 아님)

구독 레벨 Defender for Servers 플랜(Standard/P2) 및 MDE.Windows 확장 배포 상태 정상 확인함(az security pricing show, VM Extensions 블레이드로 확인)

알람 발생 시각과 예약 검사/Windows 업데이트 스케줄이 겹치는지 대조하여 

아래 공식 문서 기준 스케줄/리소스 조정 옵션을 검토 요청:

Schedule antivirus scans(https://learn.microsoft.com/en-us/defender-endpoint/schedule-antivirus-scans)

Schedule antivirus scans using PowerShell(https://learn.microsoft.com/en-us/defender-endpoint/schedule-antivirus-scans-powershell)

MDAV scan considerations and best practices(https://learn.microsoft.com/en-us/defender-endpoint/mdav-scan-best-practices)

 

문의 사항:

위 1차로 저희측에서 공유한 내용 외 첨부한 이미지의 프로세스 관련하여 MS 에서 권장하는 메모리 최적화, 경량화 설정이 별도 있는지 확인 부탁드립니다.

 

추가적으로 위 프로세스들의 정상 메모리 사용 범위에 대한 참고 가능한 공식 가이드라인이 있는지도 확인 부탁드립니다.

 

[답변내용]

MDE와 관련된 프로세스와 서비스들에 대해 권장되는 리소스 최적화 및 경량화 설정과 가이드라인이 있는지에 대한 문의로 이해하였습니다.

 

현재 첨부해주신 프로세스들에 대해서는 Windows 및 MDE의 정상 구성 요소로 확인됩니다. 특히 Antimalware Service Executable(MsMpEng.exe), MsSense.exe, WMI, RPC, Windows Modules Installer Worker(TiWorker.exe), UtcSvc 모두 Microsoft에서 제공하는 기본 시스템 또는 보안 서비스에 해당합니다.

다만, Microsoft에서 해당 프로세스들에 대해"정상 메모리 사용량은 몇 MB ~ 몇 GB 범위여야 한다"와 같은 공식 가이드라인이나 기준값은 제공하고 있지 않습니다. 실제 메모리 사용량은 서버 사양, 설치된 역할 및 기능, 파일 수, 네트워크 활동량, Defender 정책 구성, 예약 검사 수행 여부, Windows Update 수행 상태 등에 따라 크게 달라질 수 있습니다

또한 현재 확인된 범위 내에서 저희가 별도로 권장하는 메모리 사용량 제한이나 경량화 모드와 같은 설정은 제공되지 않습니다. 대신 고사용률이 지속적으로 유지된다면 아래와 같은 성능 최적화 방안을 검토할 수 있습니다.

Microsoft Defender Antivirus 예약 검사 시간 조정

업무 애플리케이션 또는 대용량 데이터 경로에 대한 적절한 Defender 예외(Exclusion) 정책 검토

Windows Update 수행 시간과 Defender 검사 시간이 중첩되지 않도록 스케줄 분리

MDEClientAnalyzer를 사용하여 실제로 어떤 프로세스, 파일 또는 경로가 스캔 빈도가 높은지 확인 후 최적화 수행

 

특히 MsSense.exe 의 경우 EDR 센서 역할을 수행하며, 엔드포인트 Telemetry 수집, 위협 탐지, 네트워크 활동 분석 등의 기능을 담당합니다. 따라서 서버의 이벤트량, 네트워크 트래픽, 활성화된 MDE 기능에 따라 리소스 사용량이 변동될 수 있습니다.

결론적으로 언급해주신 프로세스들이 모두 정상 Microsoft 구성 요소로 판단되며, Microsoft에서 별도로 제공하는 메모리 사용량 기준치 또는 해당 프로세스만을 대상으로 한 경량화 설정은 확인되지 않았습니다. 다만 특정 시점에 지속적인 High CPU/High Memory 현상이 발생하는 경우에는 예약 검사, Windows Update, 실시간 보호 스캔, MDE 센서 활동 여부를 함께 확인하고 MDEClientAnalyzer 등을 통해 원인 분석을 진행하는 것을 권장드립니다.
